# Finite Data Production And Verification

The development producer builds JSON from explicitly selected `.mjs` data
definitions and records an `artifact-derivation-evidence@0.1.0-draft` sidecar
using `plain-data-initialization@0.1.0-draft`.

In a workspace containing `main-repo/` and `HIA/hia-jsdoc/`, run the following
from `main-repo/`.

```powershell
pnpm run json-resource:jsdoc-config:build
```

The command writes a fresh `dist/jsdoc-config-production-*` directory containing
the generated `schema.json`, `derivation-evidence.json`, three JSON documentation
artifacts, a package-root draft sidecar under `package/evidence/`, and a final
`report.json`. Input repositories are read-only. A directory
without the final report represents an incomplete attempt. Repeated builds use
separate directories and deterministic report/file contents.

## Production Scope

The producer executes finite native data operations over selected declarations.
It uses real objects and arrays, native `structuredClone`, shallow object spread,
`Object.freeze` and successful property writes. Object identities are observed
with a `WeakMap`. Events describe this actual JSON production and carry the
`producer-recorded` origin.

Supported inputs contain const data declarations, explicit relative named
imports, literal values, static own-property reads and the operations above.
An object spread must be the first property and occur once. An array spread must
be the sole array element, such as `[...knownArray]`, with a previously produced
dense ordinary array. Its new mutable shell preserves child identities and
original slot sources through the existing same-type `spread` event. Mixed or
multiple spreads, sparse arrays and other iterable values are rejected.
Later static fields
are recorded as writes. Unknown calls, dynamic keys, external imports, import
cycles, prototype-related keys, duplicate declarations, duplicate initial fields,
foreign/frozen writes and array writes are rejected. Input syntax, graph size,
trace size, output expansion, provenance and text have explicit limits.

Function declarations are retained as source context without executing their
bodies. This producer does not load arbitrary ESM modules. Its production claim
covers the finite data build. Wrapper runtime state and producer authenticity
remain unverified.

## Independent Verification

The SDK reader checks the trace. A separate static analyzer reads original
definition bytes and builds its own abstract graph. The required development
gate checks source/output digests, the selected export JSON tree, original value
sources, property declarations, overwritten field history and shared container
identity. Each array element's value source is checked independently. Array-slot
declarations follow the draft rule's array-creation range.
Literal, binding, cloning, freezing and spreading event positions and counts
are checked separately. Selected field writes are checked through current and
overwritten declaration sources, including cases with identical output JSON.

Input paths are relative to the explicitly authorized source root. Output paths
are relative to the caller-bound output root. The verifier receives actual output
bytes directly and never guesses that output root. Missing evidence, unsupported
versions, changed digests, value/source conflicts and changed sharing reject
the selected-scope gate. Unselected values and full module execution are outside
this result's coverage.

The additional package-root record uses `src/` and `schemas/` paths, so installed
consumers can resolve every resource beneath the runner package. Its exact
versioned subpath is
`evidence/hia-jsdoc-config-1.0.0.derivation-evidence-0.1.0-draft.json`.
The maintained runner package includes this record. Its source and schema byte
digests must remain current. The association audit requires this installed record
for the current JSDoc configuration and rejects missing or invalid evidence.

The JSDoc command also compares generated bytes with current and legacy
distributed resources, then runs the actual JSONdoc SDK producer and independently
checks every value and JSON source-map range. The sidecar retains resource-level
coverage. The separate verification report describes its selected-export scope.
