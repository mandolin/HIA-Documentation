# Reading and support

Check the current section, topic, language and version before reading. Desktop rails and narrow-screen disclosures lead to the same destinations. Keep long signatures and code scrolling within their blocks, and keep focused controls and line targets visible below fixed headers.

Search is partitioned by language and version. No matches, loading and index failures are different states; retain a static directory on failure. Missing translations identify the source language and available routes instead of treating translated navigation as translated prose.

Reading settings control presentation such as theme, wrapping and line numbers. Persistence depends on the host's stated behavior. Settings do not change document identity, publication authority or version. Text, ordinary links and necessary directories remain available without scripts.

Identify each example's full name, license, source and scope. The API Portal and preference guide of BP/bp-docs-js-cookie are separate entries, not the product website or all demonstration projects.

For non-sensitive reports, provide versions, public inputs, reproduction steps and expected versus actual outcomes. Report sensitive issues through the private maintainer channel without disclosing source secrets, tokens, local paths or unpublished archives. Follow each owning repository's license and contribution requirements.
